# 책 입력을 받는 경로 미리보기 — PLI-96 / #116

현재 후속 작업은 `origin/dev`의 `6ee3bc7`에서 새로 만든 **`feat/#116-pli-96-preview-optimal-order`**에서 진행한다. 미리보기 내부의 테스트모드와 최단 방문 순서만 변경한다. 외부 `books` 입력, `BookNavigationSession` 필드·생성 계약, 안내/도착 화면과 전달 방식은 변경하지 않는다. commit·push하며 PR 생성과 dev 병합은 별도 요청을 기다린다.

현재 범위는 **일반 입력/테스트모드 모두 311-B 고정 출발에서 모든 책을 방문하는 최단 순서를 계산·표시하고 기존 session으로 전달**하는 것이다. 1권은 그대로, 2권은 2개, 3권은 6개 순서를 실제 A* 이동거리로 비교한다. 시속 5km 고정이므로 최단 거리가 최소 예상 시간이다. 마지막 책에서 종료하며 출발점으로 돌아오지 않는다. 실시간 안내·도착 화면의 병렬 개발 코드는 건드리지 않는다.

## 책 식별자와 전달 흐름

- `BookClient.search`는 Primo `pnx.control.recordid.first`를 읽고 `primo:<recordID>`를 `Book.id`와 `Book.controlNumber`에 보존한다. ISBN은 별도 필드다.
- `Book.recordKey`는 찜·바구니 중복 판정용이며, controlNumber가 있으면 이를 쓰고 없으면 서지정보 조합을 사용한다. `recordKey`나 ISBN을 원본 Primo recordID로 간주하지 않는다.
- 검색의 `bookSelected`는 받은 Book을 `BookDetailFeature.State.book`에 넣는다. 추천도 BookRecommendationClient에서 BookClient의 메타데이터와 추천 표지를 합쳐 같은 Book으로 상세에 전달한다.
- 상세의 미리보기는 `[store.book]`을 전달한다. 바구니는 선택 ID가 현재 목록에 존재하는 책만 원래 목록 순서로 전달한다. 전체 바구니·선택 집합·원본 Book을 바꾸지 않는다.
- `BookRoutePreviewView(books: [Book])`는 전달받은 책 배열을 순서·ID·controlNumber·나머지 메타데이터 그대로 기본 목적지로 보관한다. 자동으로 동물농장으로 교체하거나 도서 ID를 보고 테스트 모드를 추론하지 않는다. 화면 안에서 선택한 테스트 목적지도 상세·바구니의 원본 배열이나 선택 상태에 반영하지 않는다.
- 책 상세 최하단의 `바로 안내 시작`은 해당 `store.book` 한 권을 경로 미리보기에 전달하고 `fullScreenCover`로 연다. 지도 위 상세 바텀시트에서도 시트 내부 push가 아닌 독립 전체 화면이 되며, 미리보기의 뒤로가기는 해당 전체 화면만 닫고 원래 상세로 돌아온다. 도보·단계·거리 아래의 중복 미리보기 버튼은 제거한다. 실제 안내를 즉시 실행하거나 동물농장으로 자동 교체하지 않는다. 장바구니는 기존 선택 도서 배열 전달을 유지한다. 입력은 진입 시점의 값 스냅샷이며 실시간 Binding 계약은 아니다.
- 검색·추천 외의 Book이 항상 Primo 식별자를 가진다고 가정하지 않는다. 실제 소장 위치 해석을 연결할 때 출처·식별자 유효성을 확인해야 한다.

## 기존 코드와 재사용 경계

- `Features/IndoorMap/IndoorRouteSettingsView`는 `IndoorMapFeature`의 `ShelfDestination`과 계산된 경로를 표시하는 기존 단일 서가 화면이다. 책 배열을 받는 화면으로 바꾸지 않는다.
- 추후 실제 지도는 `IndoorMapView` / `IndoorMapKitView`, 경로 계산은 `IndoorRouteClient` / `IndoorRouteSearchEngine`, 상태·취소·오류 처리는 기존 `IndoorMapFeature`를 참고하거나 재사용할 수 있다.
- Book의 공유 계약은 바꾸지 않는다. 최신 dev의 `BookShelfMapFeature`와 `BookHoldingShelfResolver`가 별도 소장 정보의 청구기호를 실제 fixture에 연결한다. 기본 모드에서는 전달받은 Book으로 기존 소장 조회·로딩/오류/재시도를 사용하며, 테스트모드 버튼을 누른 경우에만 사용자 제공 세 책의 소장 정보를 주입해 해당 테스트의 API 조회를 생략한다. 계산 후 도서 카드·경로 요약은 최적 방문 순서로 표시하지만 원본 입력/Store의 책 목록은 재정렬하지 않는다.
- 기존 `IndoorMapView`/`IndoorMapKitView`와 서가 강조·카메라 기능을 그대로 사용한다. 가짜 Canvas 도면·점선 경로·위치 마커는 제거했다. 지도와 레이블을 읽은 뒤 목적지 층을 선택하고 서가 도형에 카메라를 맞춘다. 지도 영역 자체를 하단 패널 위로 제한해 목적지뿐 아니라 로딩·실패·재시도 UI도 패널에 가리지 않게 한다.
- 실제 도서의 `길안내 받기`와 이 알파 미리보기는 별도 진입점으로 보존한다. dev의 실제 소장 조회·1~3권 제한·검색/상세/바구니 상태는 변경하지 않는다.
- 일반 모드도 기존 소장 조회·서가 해석이 끝나면 아래 navigation-only 로더와 기존 `IndoorRouteSearchEngine`을 사용한다. 소장 정보가 로딩/실패하거나 서가가 0개/여러 개면 임의로 한 곳을 고르지 않는다. 재시도·테스트 전환으로 입력이 바뀌면 이전 계산을 취소하고 새 결과만 수용한다. 기존 Book·소장 조회·resolver·A*는 변경하지 않는다. 기존 테스트 로더의 이름은 호출 호환을 위해 유지하되 일반 요청에서도 재사용한다.

## 다른 페이지에서 넘기는 방법

```swift
// 책 상세: 해당 페이지 담당자가 기존 버튼 동작에 연결한다.
BookRoutePreviewView(books: [book])

// 바구니: 해당 페이지 담당자가 선택 목록을 정리해 전달한다.
BookRoutePreviewView(books: selectedBooks)

// 입력 없는 상태도 테스트 버튼을 사용할 수 있다.
BookRoutePreviewView()
```

입력 배열 자체는 빈 목록이나 상한 초과도 보존하지만, 서가 조회는 기존 `BookShelfMapFeature`의 **ID가 서로 다른 1~3권** 계약을 그대로 따른다. 조회할 수 없는 입력은 안내하고 일부만 선택하거나 임의의 테스트 책으로 대체하지 않는다. 이 경우에도 테스트모드를 선택할 수 있다.

`경로 미리보기` 제목 아래 `테스트모드` 버튼을 둔다. 누르면 현재 목적지 목록을 인물 과학사·미움받을 용기 2·노르웨이의 숲으로 교체하고 기존 서가 매칭 후 6개 방문 순서를 비교한다. `고정 목데이터 · 도서 3권 최단 방문 순서 테스트` 문구는 이 버튼을 선택했을 때만 보인다. Store 교체 시 이전 로딩은 취소한다. 일반 입력도 동일한 최단 순서 계산을 사용한다.

## 확인 방법

1. 한 권 또는 여러 권을 전달해 진입하면 전달한 책들이 표시되고 테스트 문구는 보이지 않는다. 빈 배열이면 도서 입력 대기 안내가 표시된다.
2. 제목 아래 `테스트모드`를 누르면 세 테스트 책과 안내 문구가 표시된다.
3. 로딩·계산 후 `311-B → 미움받을 용기 2(304-A) → 인물 과학사(339-B) → 노르웨이의 숲(329-A)` 순으로 표시된다. 목적지 3개를 강조하고 실제 최단 방문 경로를 파란색으로 그린다. 총 약 89.630306m / 64.533821초 / 7단계다. 카메라는 조회 층의 출발·목적지·전체 경로에 맞춘다.
4. 미리보기에서 뒤로가도 원본 도서·바구니 선택은 바뀌지 않는다. 다른 책으로 새 진입하면 다시 입력 책을 기본 목적지로 사용한다.

## 한 권 기준 디자인

- 상단 도면 영역과 하단의 둥근 다크 패널을 사용한다. 하단에는 뒤로가기, 도보 시간·단계·거리와 출발 버튼, 내 위치→책 경로 요약, 도서 및 청구기호 카드를 배치한다.
- Button·Label·ScrollView·SF Symbols 등 SwiftUI 기본 컴포넌트와 기존 BookCoverView를 재사용한다. 하단 콘텐츠는 큰 글씨·작은 화면에서도 스크롤할 수 있다.
- 지도는 앱에 포함된 실제 도서관 IMDF다. 일반/테스트 경로가 계산되면 거리, 시속 5km 기준 도보 시간, 그룹 전환 횟수 + 1의 단계를 표시한다. 경로가 없거나 현재 입력과 계산 결과가 다르면 출발할 수 없다. 유효한 전체 결과가 있으면 출발 버튼을 활성화한다. 엣지 개수는 안내 단계 수로 취급하지 않는다. 층 메뉴에서 조회 층을 변경할 수 있다.
- 도서명·저자·표지는 현재 목적지의 Book을, 소장 위치·청구기호는 해당 도서의 조회 결과를 사용한다. 테스트 모드에서만 아래 목데이터를 사용하며, 실제 확인하지 않은 대출 상태를 만들어내지 않는다.

- 출발 노드: sidecar에 명시된 `6d22ecc9-b697-4d48-a9d8-4771a6d36bcb`. 서가 도형 중심이나 현재 GPS가 아닌 **311-B에 배정된 통로 노드 좌표**를 수동 출발점으로 사용한다.
- 도착 서가: 기존 청구기호 검색으로 찾은 `337-A`, 도착 노드는 위의 `68ed0070-4842-4488-b381-3cf387733b51`이다.
- 기존 A* 엔진의 `.shortestDistance` 결과는 **33개 엣지, 58.639284m, 3층 단일 경로**다. 경로의 실제 좌표를 기존 `IndoorMapKitView` polyline으로 표시한다. 출발·도착 서가 도형과 경로를 합친 범위에 여백을 더해 카메라를 맞춘다.
- 명시적 연결이 없거나 그래프가 끊기면 오류를 표시한다. 가까운 노드로 대체하거나 임의의 직선을 그리지 않는다. 그룹은 안내 방향이나 통행 우선순위로 자동 해석하지 않는다.

### 도보 시간·그룹 기반 단계

- `RoutePreviewGuidance`는 기존 탐색 결과를 후처리한다. 시간은 **거리(m) × 3,600 / 5,000 = 초**, 초 / 60 = 분이다. 10m는 7.2초(0.12분)이며, 실제 311-B→337-A는 58.639284m / 42.220285초 / 화면 `0.70 min`이다. 분은 소수 둘째 자리로 표시하고 실제 시간 계산에는 반올림 전 거리를 사용한다. 혼잡·대기 시간은 포함하지 않은 추정치다.
- 원본 GeoJSON의 선택적 `group_id` UUID를 DTO와 RouteEdge에 보존한다. `group_name`이나 엣지 개수·각도로 그룹을 추정하지 않고, 실제 경로의 **연속한 두 엣지의 UUID가 다를 때** 단계를 나눈다. A→A→B는 2단계, A→B→A는 3단계다. 미배정(nil)끼리는 동일 구간이며 미배정↔배정은 전환이다.
- 두 엣지 사이에 실제로 지나가는 연결 노드를 경로 순서로 찾는다. 역방향·통로 중간 가상 출발도 기존 엔진의 nodeIDs/edgeIDs 계약으로 해석한다. 시작=도착은 전환 없는 1단계·0초다. 그룹이 없는 기존 자료도 1단계로 처리하며 경로 비용·방향·접근성·거리에는 영향을 주지 않는다.
- 전환 노드는 현재 층에만 24pt 주황 테두리 원형 마커로 표시한다. 서가 레이블에 가려지지 않도록 위에 표시하며, 접근성 이름은 해당 단계 시작으로 제공한다. 경로·층·전환 목록이 바뀌거나 경로가 해제되면 기존 마커를 정리한다. 기존 일반 지도는 전환 목록 기본값이 비어 있으므로 표시가 바뀌지 않는다.
- 실제 테스트 경로는 **그룹 전환 2회 → 3 steps**다. 전환 노드 UUID는 `e43c6135-24a2-43a9-ba62-a9d6cf03cb76`, `6ec3f119-b41f-40e8-afe0-3c3aaccc55bd`다. 이는 좌회전/우회전 판정이나 실시간 안내 시작 완료를 의미하지 않는다.

## 일반 도서 경로와 실시간 안내 담당자 인계

1. 상세/바구니의 진입 계약은 기존 `BookRoutePreviewView(books:)` 그대로다. 기본 입력에 목데이터를 주입하지 않는다.
2. `BookRoutePreviewRequest`가 기존 Store의 소장 조회·서가 해석 완료를 확인한다. 모든 도서의 서가가 정확히 한 곳일 때만 전체 경로를 계산한다. API/지도/서가 오류는 표시하고 출발을 막는다.
3. 시작은 항상 3층 311-B의 명시적 연결 노드다. 모든 방문 순서를 실제 이동거리로 비교해 가장 짧은 순서로 `stops`/`legs`를 함께 채운다. 단방향 구간은 역방향과 별도로 계산하고 끊긴 순서는 제외한다. 같은 계산 거리라면 먼저 열거한 입력 기준 순서를 유지한다. 같은 서가의 여러 책도 모두 보존하고 0거리 구간을 허용한다. 전부 방문 가능한 순서가 없으면 오류이며 일부 책을 생략하지 않는다. 손상 자료·측정 누락·취소는 순서 불가능으로 숨기지 않는다.
4. 단계는 전체 엣지 순서에서 계산한다. 책 사이 경계라는 이유만으로 단계를 추가하지 않고, 그 지점의 엣지 그룹이 바뀔 때만 추가한다.
5. 출발은 `fullScreenCover(item:)`로 **`BookNavigationView(session:)`**를 연다. View의 `let session: BookNavigationSession`을 이어서 사용하면 된다. 이 값은 방금 계산한 값 스냅샷이며 수신 화면에서 API를 다시 조회하거나 경로를 재계산하지 않는다.

| session 필드 | 전달 내용 |
| --- | --- |
| `stops` | 방문 순서의 각 `book`(원본 ID/controlNumber 포함), `holdings`(소장처·청구기호), `shelf`(fixture·층·도형) |
| `legs` | `stops[index]`로 가는 구간별 `IndoorRoute`. 첫 구간은 311-B, 이후는 이전 책의 서가에서 출발 |
| `route` | 전체 연결 경로. `nodeIDs`·`edgeIDs`·층별 `segments`·`floorChanges`·총 `distanceMeters`·거리 추정 여부·출발 연결 정보 |
| `guidance` | 전체 `stepCount`, 순서 있는 `groupTransitionNodes`(UUID/좌표/층), `walkingSeconds`·`walkingMinutes` |
| `graph` | UUID로 조회 가능한 원본 노드·엣지·그룹 UUID·geometry·layoutVersion |
| `origin`, `start` | 311-B 서가와 수동 출발 위치. **실제 사용자의 현재 위치가 아니다** |
| `map`, `shelfLabels` | 계산에 사용한 IMDF와 서가 레이블 |
| `id` | 한 안내 입력 스냅샷을 구분하는 UUID |

첫 단계는 1이며 `guidance.groupTransitionNodes[index]`가 `index + 2`단계의 시작 노드다. 각 책의 도착 노드는 `legs[index].nodeIDs.last`다. 전체 경로의 `destination`은 마지막 책의 ShelfKey이므로 모든 책의 정보는 반드시 `stops`/`legs`에서 조회한다.

현재 `BookNavigationView`는 제목·개발 예정 안내·뒤로가기만 있는 빈 화면이다. 실시간 위치 수신·경로 투영·단계 진행·재탐색·도착 판정은 후속 담당자의 구현 범위다. 경로가 끊겼거나 층간 연결/실측 거리 자료가 없으면 기존 오류를 유지한다. 임의의 직선이나 층간 거리를 만들어내지 않는다.

## 검증

### 최단 방문 순서 후속 작업

- 원본 모델·로더·A*와 미리보기 테스트 자료를 엄격한 동시성 경고 없이 컴파일했다. 실제 번들·모든 6개 순서 독립 대조·외부 입력 순서 6가지·2권·단방향 우회 순서·전체 단절·동일 서가·기존 A* 회귀 등 **24개 테스트가 통과**했다.
- 사용자 제시 순서 `[인물 과학사, 미움받을 용기 2, 노르웨이의 숲]`의 6개 경로 거리는 열거 순서대로 약 `[162.728712, 143.756278, 89.630306, 106.515988, 117.114529, 152.972644]m`이며 세 번째가 최단이다. 구간 결과를 방향별로 재사용해 같은 구간을 재탐색하지 않는다.
- 외부 페이지·Book·BookNavigationSession·실시간 안내/도착 View·원본 자료·패키지 설정 변경은 없다. 기존 전체 앱 매크로 승인/SwiftSyntax 문제로 TCA 연계 테스트 실행·전체 앱 통합 검증은 별도 미확인이다.

### 일반 도서·안내 입력 후속 작업

- 원본 Domain/로더/A*를 별도 검증 모듈로 컴파일하고 새 `BookNavigationSessionTests` 5개와 기존 시간·단계/경로 테스트 15개, 총 **20개**를 실행해 통과했다. 일반 Book ID·1권·3권 순차 이동·동일 서가 0거리 구간·부분 실패·입력 검증을 포함한다.
- 소장 조회 완료/재조회/실패 및 복수 서가를 다루는 `BookRoutePreviewRequest`의 TCA 연계 회귀 테스트를 추가했다. 전체 TCA 앱 테스트 실행과는 구분하며 기존 패키지 매크로 승인/SwiftSyntax 해석 문제에 대한 검증 제한은 그대로다.
- 원본 `BookNavigationView`와 도메인·로더를 사용하는 별도 iOS 호스트에서 일반 Book ID로 계산한 33개 엣지·58.639284m·3단계·전환 노드 2개를 수신하는지 assert로 확인했다. iPhone 17 Pro / iOS 26.5에서 `fullScreenCover`의 전체 화면·제목·뒤로가기를 시각 확인했다. 실제 TCA 미리보기 진입/라이브 API 호출의 전체 앱 통합 검증은 아니다.

### 시간·그룹 단계 후속 작업

- 원본 Domain·로더·A* 코드를 별도 모듈로 컴파일해 `RoutePreviewGuidanceTests`와 기존 `IndoorRouteSearchTests`를 실행했다. 2개 suite / 15개 테스트가 통과했다. 그룹 없음·동일 그룹·전환·그룹 재진입·미배정 전환·역방향·가상 출발·0거리·손상 입력, 기존 독립 Dijkstra 대조·계단 정책·C5 실제 번들 경로를 포함한다. 전체 TCA 앱 테스트 통과와는 구분한다.
- 원본 POSTECH 번들 로더와 기존 A*에서 33개 엣지·58.639284m 경로가 유지되고 42.220285초·3단계·정확한 전환 노드 2개로 해석되는 것을 실행 확인했다. 기존 해시/층/매핑 손상 자료 거부 검사도 통과했다.
- 원본 MapKit 렌더러의 별도 iOS 호스트에서 두 지도 크기의 경로·전환 노드 좌표와 24pt 마커, 최상단 표시를 확인했다. 실제 TCA 미리보기 전체 화면 통합 검증은 아래 매크로 승인 제한과 구분한다.

- 상세의 전체 화면 전환은 별도 SwiftUI 호스트에서 중간 높이 상세 시트 → `fullScreenCover`의 실제 화면 크기·전달 Book → `dismiss()` 후 기존 상세 시트 복귀를 iOS 26.5 시뮬레이터로 확인했다. 실제 상세 뷰의 연결 코드·문법 검사도 통과했으며, 이는 아래 매크로 승인 문제로 실행하지 못한 전체 TCA 앱 통합 검증과 구분한다.

### 311-B 테스트 경로 단계 기록

- 원본 IMDF/서가/그래프 mapper와 새 테스트 로더, 기존 A* 엔진을 실제 Swift 실행 파일로 함께 컴파일·실행했다. 정확한 출발·도착 노드, 층 ordinal 2, 33개 엣지와 58.639284m, 그래프 진입 보정 거리 0을 확인했다.
- 해시 불일치·descriptor와 다른 노드 층·311-B 명시적 연결 누락·정방향/역방향 연결 불일치·단절 그래프를 메모리에서 만들어 모두 거부하는 것을 실행 확인했다. 번들 원본은 바꾸지 않았다.
- 기존 MapKit 렌더러와 새 로더를 별도 iOS 검증 앱에서 컴파일하고 iPhone 17 Pro / iOS 26.5에서 실제 파란 경로·출발 핀·도착 서가 강조를 확인했다. 이는 렌더러 검증이며 전체 TCA 미리보기 화면 통합 검증은 아니다.
- `BookRoutePreviewTestRouteTests`에 번들 기반 정상/오류 경로와 실제 polyline·카메라 범위 검사를 추가했고, iOS SDK와 Xcode 내장 Swift Testing 매크로로 타입 검사를 통과했다. 별도 렌더러 호스트는 390×340·320×230 영역에서 경로·출발·도착 도형의 화면 좌표와 실제 polyline 좌표를 검사한다. 전체 앱 테스트의 실행은 아래 기존 패키지 매크로 승인 문제가 해결되기 전까지 통과로 취급하지 않는다.

- 목적지 입력 변경: 새 `BookRoutePreviewDestination`과 실제 Book/목데이터를 별도 Swift 실행 파일로 컴파일해 빈 목록·한 권·여러 권의 메타데이터/순서 보존, 명시적 테스트 교체, 반복 탭의 단일 목적지 유지, 같은 도서 ID만으로 테스트 모드에 들어가지 않는 것의 검사가 통과했다. `BookRoutePreviewTests`에도 실제 화면의 서가 상태 생성 함수를 대상으로 같은 입력·모드·잘못된 입력의 무대체 검사를 추가했다. 이 TCA/Swift Testing 테스트는 앱 빌드 차단으로 아직 실행하지 못했다.
- 이전 페이지·Book 계약·공통 소장 조회/지도 reducer·기존 일반 경로 로더는 수정하지 않는다. 지도 카메라 값에 새 route 요청과 이를 처리하는 분기만 추가하며 기존 요청 동작은 보존한다. TCA 테스트·전체 앱 GUI는 아래의 매크로 활성화 승인 문제가 해결되기 전까지 통과로 취급하지 않는다.

### 실제 지도·동물농장 연결 단계 기록

- 이번 변경: 실제 원본 Swift IMDF 로더·308개 서가 인덱스 로더·소장 정보 resolver·목데이터를 별도 실행 파일로 컴파일하고 실행했다. 단일 337-A fixture 결과, 실제 층 ordinal, 알 수 없는 위치 미연결, 첨부 3파일 해시·layout_version·목적지 fixture/층/node UUID 연결 검사가 통과했다. 이 검사는 실제 최단경로나 현장 배가를 인증하지 않는다.
- 기존 IndoorMapKitView·서가 레이블·카메라/스타일 코드 원본을 별도 iOS 검증 앱으로 컴파일했다. 실제 IMDF와 같은 목데이터 검색 결과를 전달해 iPhone 17 Pro / iOS 26.5에서 337-A 주황색 강조와 패널 위 카메라 맞춤을 확인했다. 이 검증 앱은 TCA 화면을 대체한 단순 호스트이므로 전체 BookRoutePreviewView의 통합 검증과 구분한다.
- 새 Swift 테스트 `BookRoutePreviewTests`에는 고정 목적지의 단일 강조·자동 포커스·Primo 조회 없음과 번들 파일 무결성/목적지 UUID 대조를 추가했다. 해당 테스트의 실행은 아래 Xcode 매크로 승인 문제로 아직 완료하지 못했다. 변경 파일의 Swift 문법 검사와 `git diff --check`는 통과했다.
- 현재 전체 앱 빌드 시도는 개인 키를 제외한 임시 사본에서 진행했고 기존 TCA·CasePaths·Dependencies·Perception·SwiftNavigation 매크로 활성화 승인 단계에서 중단됐다. 원본 프로젝트·패키지 잠금·전역 매크로 신뢰 설정은 바꾸지 않았다. 최신 실제 IMDF 미리보기의 전체 앱 빌드·화면 이동·렌더링 검수는 남아 있다.

### 앞선 다크 레이아웃 단계 기록

- 다크 레이아웃은 원본 Book·BookText·공통 BookCover 구현·BookRoutePreviewView를 별도 iOS 검증 앱으로 함께 컴파일하고 iPhone 17 Pro / iOS 26.5 시뮬레이터에서 렌더링했다. 샘플 Book만 전달했으며 실제 API·위치 요청은 실행하지 않았다.
- 기본 글씨 화면에서 버튼 줄바꿈과 상태바 겹침을 보정했다. 접근성 글씨 크기에서는 출발 버튼을 아래 줄로 내려 시간·단계·거리 영역의 폭을 확보한다.
- 실제 iOS Simulator SDK에서 원본 Book·BookText와 BookRoutePreviewView·BookBasketView의 타입 검사를 통과했다(Swift 5 / MainActor 기본 격리).
- BookDetailView 문법 검사, Xcode 프로젝트 plist 검사, git diff --check를 통과했다.
- 비밀 설정을 제외한 임시 사본의 전체 앱 빌드는 기존 잠금 파일의 xctest-dynamic-overlay 항목 누락으로 먼저 중단됐다. 임시 사본에서 의존성을 해석한 뒤에는 기존 TCA 등 패키지 매크로 활성화 확인에서 중단됐다. 원본 Package.resolved나 매크로 신뢰 설정은 변경하지 않았다.
- 전체 앱 빌드 성공·실제 화면 push/pop·바구니 선택 유지의 조작 검증을 완료한 것으로 취급하지 않는다. 위 확인 방법에 따른 GUI 검수는 남아 있다.
