# 선택한 책과 서가 연결

Refs #53. 책의 식별자와 명시적으로 지정된 지도 서가 키를 연결하는 규칙을 준비한다.
사용자 확인에 따라 현재는 합의된 도서 위치 필드·응답 샘플이 없어 테스트용 자료로 검증한다.

## 현재 구현과 경계

`Domain/IndoorMap/BookShelfResolver.swift`는 책 식별자와 선택적 `ShelfKey`를 입력받아
`ShelfDirectory`의 서가·층·도착 노드에 연결한다. `BookShelfSelection`은 지도 연결 규칙의 입력이며
도서관 API 응답 모델이나 다른 개발자와 합의한 소장 정보 계약이 아니다.
기존 `Book`·`BookClient`·책바구니 화면은 수정하지 않는다.

입력 책마다 `BookShelfResolution` 하나를 같은 순서로 보존한다. 실패도 책 식별자와 함께 남기며
위치 정보 없음, 다른 지도 데이터셋, 등록되지 않은 서가, 빈 책 식별자를 구분한다.
구역 이름·청구기호·제목에서 실제 서가를 추측하거나 가까운 서가로 대체하지 않는다.

모든 책이 연결된 뒤 `groupedDestinations()`를 호출하면 같은 `ShelfKey`를 한 방문 대상으로 묶는다.
각 묶음에는 연결된 모든 책 식별자가 남는다. 묶음의 순서는 입력에 처음 등장한 순서이며,
최단 방문 순서는 #54에서 계산한다. 빈 선택이나 연결 실패가 있으면 오류를 반환해 일부 책을
누락한 목록이 정상 경로 입력으로 사용되지 않게 한다.

책 제목·표지 등은 호출자가 보관한 기존 `Book` 복사본과 식별자로 연결한다. 요청 시점의 책과
계산 결과 보관·책바구니 UI 연결은 #55에서 담당한다. 실제 API 위치를 `ShelfKey`로 바꾸는
어댑터와 복수 소장본 선택 정책은 도서 담당·지도 자료 담당과 합의한 뒤 연결한다.

## 테스트용 자료

`IndoorMapTests/BookShelfMappingTestFixture.swift`의 책은 테스트에서만 생성하며 앱의 검색·추천
데이터나 도서관 기본 지도에 주입하지 않는다. 원본 C5 가상 서가 디렉터리를 이용한다.

| 책 식별자 | 명시적인 테스트 연결 | 확인 목적 |
| --- | --- | --- |
| test-book-a | c5-demo / mock-01 | 서가·층·도착 노드 연결 |
| test-book-b | c5-demo / mock-02 | 다른 층의 목적지 연결 |
| test-book-c | c5-demo / mock-01 | 같은 서가의 여러 책 보존 |
| test-book-no-location | 없음 | 실패 이유와 책 보존·부분 성공 차단 |

`BookShelfResolverTests`는 위 자료와 다른 데이터셋·알 수 없는 키·빈 선택·빈 책 ID를 검증한다.
실제 API를 호출하거나 키를 사용하지 않는다.

## 실제 서가 인덱스 수령

사용자가 `shelfdata.json`과 활용 가이드를 전달했다. [서가 인덱스 자료](ShelfIndexData.md)에
필드 의미와 빈 서가·기타 분류 처리 원칙을 기록했다. 308개 항목이 모두 현재 IMDF fixture 이름·층과
일치함을 확인했다. `sequence`는 촬영 순서이며 최적 방문 순서에 사용하지 않는다.

사용자가 가이드 표의 시작·끝 설명이 뒤바뀐 오기임을 확인했다. `callStart`·`classStart`가 시작이고
`callEnd`·`classEnd`가 끝이다. 겹치는 경계값의 포함 기준은 별도 확인 전까지 확정하지 않는다.
이 자료 수령으로 실제 청구기호 검색이나
길찾기 도착 노드 연결이 완료된 것은 아니다.

## 협업 확인 후 남은 연결

- 도서 담당에게 책·소장 위치 응답과 전달 필드를 확인한다. 현재 `Book`에는 소장 위치가 없고
  `BookClient`의 delivery는 표지 링크만 해석한다.
- 수령한 서가 인덱스의 경계값 포함·비교 규칙을 담당자에게 확인하고 실제 서가 도착 노드 자료를 받는다.
  소장 구역 코드가 개별 서가 번호라는 전제를 두지 않으며, 층·자료실이 다른 동일 표기와 복수 소장본도 확인한다.
- 합의한 실제 위치 정보에서 지도 키를 결정하는 부분을 연결하고 실제 예시로 검증한다.
  자료 준비 전에는 #53 전체가 완료됐다고 판단하지 않는다.

현재 브랜치는 #52의 지도·해시 계약 변경을 기반으로 분기했다. #52의 노드·서가 자료 연결은
기존 PR #66에서 이어가고, #53 PR은 책과 서가 연결 변경만 별도로 비교한다.
최종 dev 반영 전 #52 병합 상태에 맞춰 비교 기준을 정리한다.
