# 선택한 책과 서가 연결

Refs #53. 책의 식별자와 명시적으로 지정된 지도 서가 키를 연결하는 규칙을 준비한다.
사용자 확인에 따라 현재는 합의된 도서 위치 필드·응답 샘플이 없어 테스트용 자료로 검증한다.

## 현재 구현과 경계

`Domain/IndoorMap/BookShelfResolver.swift`는 책 식별자와 선택적 `ShelfKey`를 입력받아
`ShelfDirectory`의 서가·층·도착 노드에 연결한다. `BookShelfSelection`은 지도 연결 규칙의 입력이며
도서관 API 응답 모델이나 다른 개발자와 합의한 소장 정보 계약이 아니다.
기존 `Book`·`BookClient` 계약과 책바구니에 담고 삭제하는 동작은 유지한다.

## 검색 결과·책바구니에서 여는 임시 서가 지도

책 매핑 중복 대응은 사용자가 추후 처리하기로 했으므로 이번 구현 범위에서 제외한다.
책마다 서가 하나가 결정됐다고 가정한 목업을 사용하며 길안내 입력은 한 번에 **1~3권**이다.

검색 결과의 `길안내 받기`는 한 권을 `BookShelfMapView`에 전달한다. 책바구니에서는 선택한
1~3권을 보관 순서대로 전달한다. 선택이 없거나 4권 이상이면 길안내 버튼을 비활성화하고,
reducer와 지도 초기화에서도 같은 제한을 검증한다. 제한은 길안내 입력 수량에만 적용하며
바구니에 담는 수량이나 여러 권을 선택해 삭제하는 동작은 제한하지 않는다.
화면의 `뒤로`는 `dismiss()`로 이전 화면에 돌아간다. 독립된 지도 상태를 사용하므로 홈 지도의
층·카메라와 검색어·검색 결과·바구니를 보존한다. 실제 경로 탐색은 시작하지 않는다.

도서 위치 데이터는 다른 담당자의 작업이므로 API나 공유 `Book` 모델을 확장하지 않고 목업을
사용한다. 선택한 책의 제목과 함께 **임시 서가 위치**임을 표시한다. 책 ID로 아래 세 곳 중
하나의 fixture를 고정해서 선택한다. 같은 책은 검색·바구니 진입이나 선택 순서와 관계없이
같은 목업 서가에 연결된다. 실제 소장 위치를 뜻하지 않으며 서로 다른 책이 같은 서가를 쓸 수 있다.

| 목업 층·서가 | 고정 fixture |
| --- | --- |
| 3층 `365-B` | `S-3F-616-B` |
| 3층 `367-B` | `S-3F-612-B` |
| 3층 `369-B` | `S-3F-608-B` |

이전의 공통 목업 청구기호와 `3층 목업`·`4층 목업` 전환 UI는 제거했다.
이번 화면은 `BookShelfRangeMatcher`로 범위를 검색하거나 복수 후보 중 첫 서가를 선택하지 않는다.
기존 범위 비교 코드와 테스트는 후속 작업을 위해 보존하되 화면의 목업 연결에는 사용하지 않는다.

연결한 서가 도형과 레이블을 주황색으로 강조하고 전체 서가가 보이도록 지도를 확대한다.
각 책의 서가 버튼으로 해당 서가에 포커스하고, 여러 권이면 `모두 보기`로 전체에 다시 맞춘다.
강조 레이블은 일반 레이블보다 먼저 배치한다. 카메라 맞춤은 하단 안내 카드를 제외한 지도 영역을
기준으로 하며, 지도가 카드 뒤까지 확장되어 서가가 아래로 치우치지 않게 한다.
서가 레이블 로딩 실패·재시도와 지연 응답 처리는 기존 지도 기능을 사용한다.

수동 확인은 검색 결과의 `길안내 받기` → 서가 하나 강조 → `뒤로` 후 검색 상태 유지,
바구니에서 1~3권 선택 → 길안내 → 책별 서가 강조·포커스·전체 보기 순서로 진행한다.
4권 이상 선택하면 길안내가 비활성화되어야 한다. 실제 도서 위치나 최적 방문 경로를 확인하는
검사는 아니다.

2026-10-27 iPhone 18 Pro / iOS Simulator 27.0에서 전체 158개 테스트 함수·309회 실행이
통과했고 실패·skip·xcresult 런타임 경고는 0이었다. 단일 도서·3권 지도 표시와 다크 모드,
검색 결과·바구니 보존, 책별 목업 일관성, 1~3권 허용·빈 선택·4권·존재하지 않는 책 거부,
레이블 재시도와 로딩 중 dismiss의 요청 취소를 검증했다.
결과 번들은 `/private/tmp/postech-pr68-single-shelf-three-books-final.xcresult`다.

2026-10-28 게시 전 검증에서는 화면 재진입 레이블 복구 검사와 안전한 JSON 자료 검증까지 포함해
전체 159개 테스트 함수·310회 실행이 통과했다. 실패·skip·xcresult 런타임 경고는 0이었다.

로컬 프로젝트에는 앱 iOS 27·테스트 iOS 26 설정 차이가 있어, 현재 소스를 복사하고 Git에 저장된
기존 iOS 26 프로젝트 설정을 적용한 검증 사본에서 실행한다. 개인 프로젝트 설정과 API 키는
변경하지 않았다.

지도 표시는 실제 서가 인덱스를 사용한다. `BundledShelfLabelLoader`가 번들의 `shelfdata.json`을 읽고
각 `fixtureNumber`를 현재 IMDF fixture 이름·층에 연결한다. `IndoorMapFeature`는 레이블을
navigation과 별도로 불러와 노드 자료 준비 전에도 표시하고, 실패·재시도·늦은 응답을 처리한다.
도착 노드가 없는 표시용 레이블을 `ShelfDestination`으로 간주하지 않는다.

입력 책마다 `BookShelfResolution` 하나를 같은 순서로 보존한다. 실패도 책 식별자와 함께 남기며
위치 정보 없음, 다른 지도 데이터셋, 등록되지 않은 서가, 빈 책 식별자를 구분한다.
구역 이름·청구기호·제목에서 실제 서가를 추측하거나 가까운 서가로 대체하지 않는다.

모든 책이 연결된 뒤 `groupedDestinations()`를 호출하면 같은 `ShelfKey`를 한 방문 대상으로 묶는다.
각 묶음에는 연결된 모든 책 식별자가 남는다. 묶음의 순서는 입력에 처음 등장한 순서이며,
최단 방문 순서는 #54에서 계산한다. 빈 선택이나 연결 실패가 있으면 오류를 반환해 일부 책을
누락한 목록이 정상 경로 입력으로 사용되지 않게 한다.

책 제목·표지 등은 호출자가 보관한 기존 `Book` 복사본과 식별자로 연결한다. 요청 시점의 책과
계산 결과 보관과 실제 경로의 책바구니 연결은 #55에서 담당한다. 이번 바구니 진입은 서가 표시
목업까지만 연결한다. 실제 API 위치를 `ShelfKey`로 바꾸는
어댑터와 복수 소장본 선택 정책은 도서 담당·지도 자료 담당과 합의한 뒤 연결한다.

## 실제 서가 인덱스 수령

사용자가 `shelfdata.json`과 활용 가이드를 전달했다. [서가 인덱스 자료](ShelfIndexData.md)에
필드 의미와 빈 서가·기타 분류 처리 원칙을 기록했다. 308개 항목이 모두 현재 IMDF fixture 이름·층과
일치함을 확인했다. `sequence`는 촬영 순서이며 최적 방문 순서에 사용하지 않는다.

사용자가 가이드 표의 시작·끝 설명이 뒤바뀐 오기임을 확인했다. `callStart`·`classStart`가 시작이고
`callEnd`·`classEnd`가 끝이다. 겹치는 경계값의 포함 기준은 별도 확인 전까지 확정하지 않는다.
지도에는 실제 번호·면(`301-A`)과 청구기호 범위, 기타 분류 또는 `빈 서가`를 표시한다.
레이블의 기준점은 서가 fixture 도형 중심이며, 화면 좌표에서 겹치지 않는 레이블을 골라 표시한다.
확대하면 더 많은 레이블을 확인할 수 있다. 이 표시로 실제 도서의 범위 검색이나 길찾기 도착 노드
연결이 완료된 것은 아니다.

## 협업 확인 후 남은 연결

- 도서 담당에게 책·소장 위치 응답과 전달 필드를 확인한다. 현재 `Book`에는 소장 위치가 없고
  `BookClient`의 delivery는 표지 링크만 해석한다.
- 수령한 서가 인덱스의 경계값 포함·비교 규칙을 담당자에게 확인하고 실제 서가 도착 노드 자료를 받는다.
  소장 구역 코드가 개별 서가 번호라는 전제를 두지 않으며, 층·자료실이 다른 동일 표기와 복수 소장본도 확인한다.
- 합의한 실제 위치 정보에서 지도 키를 결정하는 부분을 연결하고 실제 예시로 검증한다.
  자료 준비 전에는 #53 전체가 완료됐다고 판단하지 않는다.

## PR 비교 기준과 검토 범위

현재 브랜치는 #52의 지도·해시 계약 변경을 기반으로 분기했으며, 선행 PR #66은 `dev`에 병합됐다.
#53의 PR #68은 `dev`를 대상으로 비교한다. PR의 범위에는 책–서가 연결 규칙과 테스트뿐 아니라
다음 지도 변경도 포함한다.

- 실제 서가 인덱스 `shelfdata.json` 308개 항목과 `BundledShelfLabelLoader`·`IndoorShelfLabelClient`.
- `IndoorMapFeature`의 독립적인 레이블 로딩·실패·재시도·취소와 응답 식별.
- `IndoorMapKitView`·`IndoorShelfLabelAnnotation`의 번호·면·범위·기타 분류·빈 서가 표시와 레이블 배치.
- 데이터 검증, 지도 표시, 레이블 수명과 복구 경로를 확인하는 회귀 테스트.

앞 절의 검색·바구니 목업 진입, 서가 강조·카메라 맞춤과 최대 3권 입력 검증도 PR에 반영된
최신 head를 기준으로 검토 대상에 포함한다. 마지막 commit이나 책–서가 연결 파일만 보지 않고
`dev`와 PR head의 공통 조상부터 누적 변경 전체를 확인한다. 로컬 확인 명령은
`git diff origin/dev...HEAD`이며, 원격 PR 검토에서는 해당 PR의 head SHA를 사용한다.
실제 도서 위치·길찾기 도착 노드 연결의 완료 여부는 이 목업·지도 표시 범위와 구분한다.
