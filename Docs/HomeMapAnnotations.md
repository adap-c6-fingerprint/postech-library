# 홈 지도: 편의시설과 찜한 책

관련 이슈: [#229](https://github.com/adap-c6-fingerprint/postech-library/issues/229)

## 표시 동작

- 계단·엘리베이터는 기본으로 표시하고, 나머지 편의시설은 왼쪽 `편의시설` 버튼으로 켜고 끈다. 조회 중인 층의 시설만 표시한다.
- 찜한 책의 하트는 편의시설 표시 여부와 관계없이 표시한다. 장바구니 목록은 사용하지 않는다.
- 같은 서가의 여러 찜과 복본은 하트 하나로 묶고, 누르면 찜한 책 수와 서가 번호를 보여준다.
- 시설과 찜한 책의 서가는 아래 에셋을 원본 색상과 픽셀을 유지해 30pt로 표시한다. 다른 공개 이용 공간은 기본 핀으로 표시하고, 비공개 사무실·기계실·창고와 일반 가구에는 핀을 만들지 않는다.
- 시설 위치는 앱에 포함된 IMDF의 실제 구역 도형에서 가져온다. 이름이나 종류가 없는 가구를 프린터 등으로 추정하지 않는다.

| 표시 대상 | 에셋 |
| --- | --- |
| 카페 니어미 | `annotation_cafe` |
| 미팅룸 | `annotation_conferenceRoom` |
| 편의점 | `annotation_convenienceStore` |
| 엘리베이터 | `annotation_elevator` |
| 게임룸 | `annotation_gamingRoom` |
| GSR·무은재 회의실·강의실 | `annotation_groupStudyRoom` |
| 찜한 책의 서가 | `annotation_liked` |
| 프린터·복사기 | `annotation_printer` |
| 릴렉스존·휴게실 | `annotation_relaxZone` |
| 계단 | `annotation_stairs` |
| 화장실 | `annotation_toilet` |
| 영상 스튜디오 | `annotation_tv` |

위에 지정하지 않은 어노테이션 에셋은 아직 사용하지 않는다.

홈과 출발 후 길안내의 현재 위치는 `MapUserLocation`·`MapUserHeading` 에셋을 함께 사용한다. 원의 중심은 실제 좌표에 두며, 홈에서는 사용자 방향을, 길안내에서는 현재 경로의 진행 방향을 헤드에 반영하고 지도 회전을 보정한다. 방향을 알 수 없으면 원만 표시한다.

겹칠 때는 사용자 위치, 경로 배지, 시설·찜, 서가 번호 순서로 앞에 그린다. 시설·찜을 선택해도 사용자 위치보다 위로 올리지 않는다. 센서·시뮬레이션·수동 위치와 MapKit 기본 위치도 같은 최상위 순서를 사용한다.

길안내의 층간 이동 배지도 `annotation_stairs`·`annotation_elevator`를 사용한다. 홈 시설 아이콘과 길안내 이동 배지는 모두 30×30pt로 표시한다. 별도 이미지가 지정되지 않은 이동 수단의 기본 표시는 유지한다.

실행 기준은 최신 dev와 같은 `com.youngmin.fingerprint-library`이며 표시 이름은 Po:book이다. 앱 이름과 번들 ID를 따로 변경하거나 `com.sano.fingerprint-library` 설치본과 혼용하지 않는다.

2026-11-03의 어노테이션 통합에서는 홈·길안내 이미지, 음수 경로 방향과 방향 누락, 계단·엘리베이터 배지, 50Hz 위치 수신에 따른 안내·카메라 갱신을 포함한 관련 검사 28개가 통과했다. 실기기 보행 검증과 전체 앱 검사는 포함하지 않는다.

이전 dev(`c281cf6`) 통합에서 관련 검사 28개가 통과했다. 이후 PR용 새 체크아웃에서는 스터디룸 이미지 파일명의 한글 정규화 차이로 에셋이 다시 누락되는 것을 확인했다. 세 배율의 파일명을 영문으로 통일하고 참조를 갱신해 체크아웃 방식에 영향을 받지 않도록 수정했다. 이미지 내용은 유지한다.

이름이 없는 공간도 도면의 `lounge`는 `휴게실`, `classroom`은 `강의실`로 표시한다. 현재 도면의 1층 휴게실 1곳과 5층 강의실 4곳에도 위 아이콘을 적용한다.

## 찜 정보는 로컬에서만 처리

찜 추가·취소, 홈 지도 진입, 편의시설 전환과 층 변경은 도서 검색·소장 API를 호출하지 않는다. 찜 목록이나 찜한 책을 근거로 만든 요청은 외부로 보내지 않는다. 기존 `BookFavoritesClient`의 UserDefaults 저장 형식도 유지한다.

위치 정보의 흐름은 다음과 같다.

1. 앱 번들의 `RecommendationDataset.json`에 포함된 812권의 소장 정보를 로컬 기본 자료로 사용한다. 파일 읽기·해석은 별도 actor에서 수행하며, 일반 조회로 저장한 최신 사본을 덮어쓰지 않는다.
2. 사용자가 일반 검색·상세 조회를 하거나 기존 추천 카드·서가 화면에서 소장 응답을 받으면, 이미 받은 응답을 `BookLocationCacheClient`로 로컬에 보관한다. 이는 찜 여부와 무관한 기존 요청의 응답 재사용이며 추가 요청을 만들지 않는다.
3. 홈은 로컬 찜 목록과 로컬 소장 사본만 결합한다. 책 번호의 `primo:` 접두어 차이를 정규화하고, ISBN으로 저장된 추천 도서도 이미 로컬에 있는 같은 ISBN의 자료만 연결한다. ISBN 검색으로 보충하지 않는다.
4. `BookHoldingShelfResolver`로 소장 위치와 청구기호 범위를 로컬 도면에 연결한다. 현재 지원 범위는 POSTECH 중앙도서관 3·4층 일반 서고(`c3b`, `c4b`)다.
5. 범위가 겹치면 후보 서가를 모두 보존하고 하트 설명에 `위치 후보`를 표시한다. 별치·스마트도서관, 청구기호 누락·범위 밖 등 확인할 수 없는 위치에는 하트를 만들지 않는다.

위치 사본은 앱을 다시 실행해도 복원된다. 일반 조회에서 새 응답을 받으면 로컬 사본과 열린 홈의 하트도 갱신된다. 위치·카메라만 바뀔 때는 표시 결과를 재사용해 청구기호 범위를 반복 해석하지 않는다. 이 사본은 지도 표시용이며 현재 대출 가능 상태를 판단하는 캐시로 사용하지 않는다.

검색 응답에서 소장 필드가 누락되거나 `delivery`가 빈 객체이면 기존 위치를 유지한다. `holding: []` 또는 `availlibrary: []`처럼 빈 목록이 명시된 경우에는 이전 위치를 제거한다. 여러 권의 검색 결과는 메모리에 한 번에 반영한 뒤 전체 저장과 변경 알림을 각각 한 번만 수행한다. 번들 자료가 최신 로컬 사본을 덮어쓰지 않는 규칙도 유지한다.

**번들과 로컬 사본 모두에 위치 정보가 없는 찜에는 하트를 표시할 수 없다.** 이를 자동 API 호출이나 임의의 위치로 보충하지 않는다. 이후 사용자가 일반 검색·상세 조회를 통해 위치 정보를 확보하면 로컬 사본으로 표시한다. 찜 표시를 위해 별도의 서버 토큰을 요구하지 않는다.

## 코드 위치

- `BookLocationCacheClient`: 일반 조회에서 받은 소장의 로컬 저장·복원·변경 알림. 네트워크 Client를 호출하지 않는다.
- `HomeMapAnnotationsFeature`: 편의시설 표시 옵션, 로컬 찜·위치 결합과 변경 구독.
- `HomeMapMarkerBuilder`: 시설 분류, 소장과 서가 연결, 서가별 하트 묶기.
- `HomeMapAnnotationController`: 현재 층의 핀 추가·제거와 원본 이미지 표시. 유지되는 핀은 재생성하지 않는다.

## 확인 방법

- 홈 진입 시 편의시설이 숨겨져 있는지 확인하고 버튼으로 표시·숨김을 전환한다.
- 위치 정보가 포함된 일반 검색·상세 응답을 받은 책을 찜한 뒤 해당 층의 하트를 확인한다. 장바구니에만 담은 책에는 하트가 생기지 않아야 한다.
- 찜을 취소하고, 같은 서가의 다른 찜이 있으면 하트가 유지되는지 확인한다. 마지막 찜을 취소하면 하트가 사라져야 한다.
- 앱을 다시 실행해 로컬 위치가 복원되는지 확인한다.
- 네트워크 없이 찜 추가·취소·홈 진입·시설 전환을 반복한다. 위치가 없는 찜도 외부 요청을 만들지 않아야 한다.

자동 검사: `BookLocationCacheClientTests`, `HomeMapAnnotationsFeatureTests`, `HomeMapMarkerTests`, `HomeMapAnnotationScreenTests`, `MapUserLocationStackingScreenTests`. 찜과 지도 표시 과정의 검색·소장·HTTP 호출 횟수를 검사하고, 일반 상세 응답을 로컬에 보관한 뒤 열린 홈의 하트가 갱신되는 경로를 확인한다. 사용자 위치와 찜·계단·엘리베이터를 같은 좌표에 놓고 시설 선택 전후의 위치 원 픽셀도 비교한다.
