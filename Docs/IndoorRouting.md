# 단일 서가 길찾기

Refs #7. `feat/#7-indoor-routing`은 사용자가 정상 동작을 확인한 시뮬레이터·가상 서가
작업 `c147af0` 위에서 분기했다. 현재 위치에서 선택한 가상 서가 한 곳까지의 경로를 미리 본다.
실제 측위·보정은 마지막 단계, 수동 출발점은 보류다. 여러 서가의 순서 최적화는 #11,
이동 중 자동 재탐색·진행 안내·도착 처리는 #16에서 연결한다.

## 수동 확인 방법

1. [시뮬레이터 설정](IndoorMapSimulation.md)대로 같은 C5 도면을 열고 Wi-Fi 위치 기반 측위를 끈다.
2. 시뮬레이터 위치를 통로에 놓는다. 홈에서 가상 서가를 선택하고 **경로 보기**를 누른다.
   navigation stack의 다음 화면인 **경로 설정**으로 이동하며 경로를 계산한다.
3. 파란 경로선과 이동거리를 확인한다. 층 버튼을 바꾸면 그 층의 경로선만 표시된다.
   계단·엘리베이터의 층별 진입/이탈 지점은 작은 파란 원으로 표시한다.
4. 하단 이동 방식 메뉴에서 **엘리베이터 우선**을 선택하면 자동으로 다시 계산한다. 계단을 제외한 경로가 없고 계단 경로는
   있으면 계단 포함 여부를 한 번 묻는다. 취소하면 계단 경로를 표시하지 않는다.
5. 시뮬레이터 위치를 옮긴 뒤 **현재 위치에서 다시 계산**을 누른다.
   표시한 경로는 계산 당시 출발점의 스냅샷이며 위치 수신마다 자동 재탐색하지 않는다.
6. 뒤로가기로 홈에 돌아오면 경로·서가 선택과 진행 중인 계산을 정리한다. 비활성화·일시 위치 오류는 진행 중인 계산과 계단 확인을 취소하되 완료된 경로를 유지한다. 복귀 후 재수신 대기 중에도 미리보기가 유지되는지 확인한다. 실제 연결 단절·권한 철회·뒤로가기 후에는 경로와 늦은 결과가 다시 나타나지 않는지 확인한다.
7. 홈과 경로 설정의 오른쪽 위 **현재 위치** 버튼은 현재 위치의 층으로 복귀한다.
   경로 설정에서는 하단 시트를 제외한 지도 영역의 중심으로 이동한다. 위치가 없으면 권한·수신 상태를 안내한다.
8. 방문 순서 시트의 핸들을 누르거나 위아래로 끌어 펼치고 접는다. 펼친 상태에서도 이동 방식 메뉴와 재계산 버튼은 하단에 유지된다.

## 화면 구성

디자이너의 2026-10-19 Lo-fi에 맞춰 홈은 흰색 제목·검색 헤더와 화면 폭을 채우는 지도,
오른쪽 위 위치 버튼, 왼쪽 아래 층 선택으로 구성한다. 기존 도서 검색 진입은 유지한다.
경로 설정은 native 뒤로가기와 제목, 현재 위치·층 버튼, 방문 순서 타임라인을 담은 하단 시트를 사용한다.

현재 #7의 목적지는 한 곳이다. 출구를 추가하지 않으며, 하단 주 동작은 실제 구현된 재계산이다.
여러 책의 방문 순서는 #11, **안내시작** 동작과 진행 안내는 #16에서 연결한다.
앱 전체 navigation 상태는 `AppFeature`가, 시트 펼침·경로 상태는 `IndoorMapFeature`가 관리한다.
위치 구독의 수명은 `AppView`에 두어 홈과 경로 설정 사이 push/pop으로 중단되지 않게 한다.

Core Location의 `locationUnknown`은 위치 재수신 대기로 분류한다. 이전 위치는 비워 새 위치 전까지
재계산을 막고 상태 문구를 표시하며, 완료된 경로는 계산 당시 출발점의 미리보기로 유지한다.
권한 철회·데이터 변경·실제 시뮬레이터 단절은 경로 무효화 사유다. 위치 구독 재시작의 초기 연결 대기를
단절과 구분해 제어 센터를 닫은 직후 경로가 사라지지 않게 한다.

## 구조와 계산 기준

- `Domain/Routing`: 순수 모델, 거리 계산, 방향별 graph index, heap 기반 A*, 현재 위치의 통로 연결.
- `Clients/IndoorRouting/IndoorRouteClient`: `@concurrent` 계산 경계와 TCA 의존성.
- `Features/IndoorMap`: 입력 스냅샷, 계산/취소/오류/계단 확인 상태, 조회 층의 MapKit overlay와 경로 설정 시트.
- `Resources/IndoorMaps/C5/cross-floor-distances.json`: C5 시연용 층간 추정 거리와 근거.

같은 층은 간선의 전체 polyline 길이를 미터로 합산한다. 층간은 별도 자료의 미터 값을 사용한다.
시간을 거리로 바꾸거나 계단·엘리베이터에 선호 가산점을 넣지 않는다. A*의 heuristic은 수평
직선거리이며 층간 거리는 적어도 양 끝점의 수평 직선거리 이상이어야 한다.
방향성·역방향 polyline·결정적인 동률 순서를 보존하고 취소 여부를 검사한다.

같은 node에서 같은 방향으로 연속되는 엘리베이터 간선은 결과의 `floorChanges`에서 한 번의 탑승으로 묶는다.
각 탑승은 원본 `edgeIDs`를 보존한다. 도보 간선이 끼거나 층 이동 방향이 바뀌면 따로 표시한다.
그래프에서 서로 다른 엘리베이터로 환승해야 한다면 별도 노드와 환승 간선으로 표현해야 한다.
작은 거리 차이를 동률로 만드는 epsilon은 추가하지 않았다. A*가 선택한 원본 경로와 거리 합은 그대로다.

엘리베이터 우선은 `.stairs` 간선을 먼저 제외하는 탐색이다. 별도의 휠체어 접근성 판정은
아니며 `.accessible` 값은 원본에 보존한다. 계단을 허용한 경우 같은 거리 기준으로 다시 계산한다.

출발점은 같은 층의 가장 가까운 polyline 지점에 연결한다. 긴 간선의 중간이면 해당 간선의
방향에 맞는 남은 부분만 계산한다. 원래 파란 점의 좌표를 보정하거나 바꾸지 않는다.
현재 좌표와 연결 지점 사이의 직선 간격은 보행 가능성을 증명하지 않으므로 경로 거리와
실선에 포함하지 않고 별도로 표시한다. 그래프의 `hard_search_radius_meters`보다 멀거나
정확도 값이 그 반경보다 크면 입력 오류로 안내한다.
센서·재생·시뮬레이션은 유한한 정확도 값을 요구한다. 수동 출처는 사용자가 지정한 정확한 점으로
해석해 정확도 메타데이터 없이도 처리하지만 좌표·층·통로 연결 반경 검사는 유지한다. 이 내부 정합성
수정으로 수동 출발점 UI를 추가하지 않는다. 층 정보 자체가 없을 때와 그 층에 routing node가 없을 때의 오류를 구분한다.

## C5 추정 거리 — 2026-10-19 사용자 결정

사용자가 실측 자료가 없으므로 임의 값을 사용하도록 지시했다. C5 개발용 기본값은 다음과 같다.

| 이동 수단 | 층당 추정 거리 |
| --- | --- |
| 계단 | 10m |
| 엘리베이터 | 3.5m |

직접 연결된 두 노드의 ordinal 차이에 층당 값을 곱한다. 예를 들어 ordinal 0→4 계단은
40m, 엘리베이터는 14m다. 실제 층고·계단 동선을 측정한 값이 아니다.
추정 구간을 하나라도 사용하면 카드에 **예상 거리**와 C5 시연용 추정값 문구를 표시한다.
이는 추정치를 포함한 그래프에서의 최단 경로이며 실제 현장 거리의 최단성 보장이 아니다.

별도 JSON은 schema·dataset_id·layout_version·연결 ID·거리·출처·근거를 갖고
`dataset.json`의 `cross_floor_distances_sha256`으로 고정한다. 기존 schema 1 데이터셋에서
이 optional 필드가 없으면 추정값을 몰래 만들지 않는다. 층간 자료가 없는 그래프는 탐색 시
자료 필요 오류로 처리한다. 실측 후 `source: measured`·근거·해시를 함께 갱신할 수 있다.
새 필드는 IM-DFrnt export에 이미 합의된 계약이라는 뜻이 아니다.

가져오기 스크립트는 시연용 추정 파일을 결정적으로 생성한다. 로컬에서 바꾼 거리 자료는
IMDFData 폴더 유무와 관계없이 `--replace` 없이 덮어쓰지 않는다.
생성할 추정치가 양 끝점의 수평 직선거리보다 짧으면 기존 파일을 교체하기 전에 실패한다.
번들 로더도 같은 하한을 검증해 탐색을 누르기 전에 잘못된 거리 파일을 식별한다. 탐색 인덱스의
기존 방어 검사도 유지하며, 불가능한 가정을 자동으로 늘려서 숨기지 않는다.

## 원본 이식과 검증

[원본 스냅샷](References/FingerprintRoutingSource.json)은 기준 HEAD와 파일별 SHA-256을 기록한다.
원본 working tree의 미커밋 변경을 수정하지 않았다. 임시 Swift 패키지에서 원본 시간 비용 코어의
32개 테스트·6개 suite를 먼저 통과시켰다. 경유지 UI 리소스를 요구하는 테스트는 #11 범위로 제외했다.

`BinaryHeap`은 그대로 이식했고 거리 계산은 좌표 타입만 맞췄다. A*의 heap·best-cost·동률 처리와
방향별 index 구조를 바탕으로 비용을 미터로 전환했다. 기존 앱의 로더·검증기를 중복 이식하지 않고
#5의 DTO→Mapper 검증 및 거리 기반 index의 방어 검증을 사용한다.

새 테스트는 독립 Dijkstra와 모든 노드 쌍 비교, 방향성·부분 간선·굽은 polyline·역방향,
시작=도착·단절·원거리·층 오류·취소, 계단 확인과 오래된 응답, 층별 overlay 정리를 검증한다.
실제 C5 번들의 같은 층·층간 경로, 거리 파일의 해시·버전·참조·출처 오류도 검사한다.

연속 엘리베이터·도보 환승·이동 방향 전환, 비활성화/재활성화·초기 재연결 대기·일시 위치 오류,

IMDF 장애물과 전체 경로의 물리적 보행 가능성은 이 계산으로 인증하지 않는다. 마지막 수동 QA와
