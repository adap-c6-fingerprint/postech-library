## 필드의 역할

| 필드 | 확인한 의미·처리 원칙 |
| --- | --- |
| `fixtureNumber` | IM-DFrnt에서 태깅한 `S-층정보-고유번호-사이드` 식별자. 현재 IMDF fixture 이름과 정확히 연결한다. |
| `floor` | `3F`, `4F` 같은 표시 층. 실제 IMDF 층 참조와 대조한다. |
| `realNumber` | 현장 서가 번호. `499A`, `499G`도 있어 문자열로 보존한다. A·B 면에서 같은 번호를 쓰므로 단독 식별자로 쓰지 않는다. |
| `side` | 아트리움을 등졌을 때 왼쪽은 A, 오른쪽은 B. 기기 방향이나 지도 북쪽을 기준으로 다시 해석하지 않는다. |
| `sequence` | 사진 촬영 순서. 원본 정수로 보존하며 방문 순서·경로 비용·서가 연결 우선순위로 쓰지 않는다. |
| `other` | 청구기호가 없는 경우의 기타 분류. 예: 영어교재, 참고도서, 학위논문. |
| `callStart`, `callEnd` | 원본 청구기호 범위 값. 시작·끝의 역할은 담당자 확인 전까지 확정하지 않는다. |
| `classStart`, `classEnd` | 원본 분류기호 값. 시작·끝의 역할은 청구기호 필드와 함께 확인한다. |

## 담당자 확인 대기

가이드 표에는 `callEnd`·`classEnd`를 시작으로, `callStart`·`classStart`를 끝으로 설명했다.
JSON 예시는 `callStart: AC1.G72`, `callEnd: AM79.K8`처럼 키 이름으로 읽을 때의 순서와 대응한다.
2026-10-27 사용자가 담당자에게 확인하기로 했으며, 답변 전에는 어느 쪽도 확정 규칙으로 구현하지 않는다.

인접 항목의 `callEnd`와 다음 `callStart`가 같은 경우도 53곳 있다. 예를 들어 `AM79.K8`이 두 서가에
함께 등장한다. 경계값의 포함 범위와 실제 도서의 전체 청구기호를 비교하는 규칙은 아직 확인 대기다.
촬영 순서나 배열 순서를 이용해 첫 후보를 임의로 선택하지 않는다.

## 남은 연결

1. 담당자에게 시작·끝의 의미와 경계값 처리 규칙을 확인한다.
2. 도서 담당과 실제 청구기호·소장 구역 등의 전달 정보를 합의한다. `other` 전용 구역도 함께 확인한다.
3. 인덱스 검색 결과를 명시적인 fixture ID에 연결하고, 전달받을 서가 도착 노드와 결합한다.
