기준
- origin/dev eea814f에서 분기한 refactor/#191-pli-150-code-cleanup.
- 동작·UI·도서/길안내 데이터 계약을 유지하는 범위의 정리다.
- Ponytail: 실제 책임·사용처를 기준으로 나누고, 새 추상화보다 기존 코드 재사용을 우선했다.

현재 구조
- App: 탭, 온보딩, 앱 수명과 기능 간 장바구니·찜 동기화.
- Features/IndoorMap: 지도 화면과 층·위치·단일 서가 길찾기 상태.
  Rendering: MapKit 어댑터·좌표 변환.
  Rendering/Annotations: 지도 전용 시설·서가·안내 목적지 표시.
- Features/BookShelfMap: 소장 정보와 청구기호를 실제 fixture에 연결.
- Features/BookRoutePreview: 도서 입력·테스트 전환·미리보기 경로 계산과 시트 배치.
- Features/BookNavigation: 확정된 세션의 실시간 안내·도착 화면.
- Clients: API·캐시·번들 파일·위치·저장소와의 경계.
- Domain/User/UserProfileSnapshot.swift: SwiftData 객체와 분리된 프로필 전달 값·검증 오류.

책을 받아 안내로 넘기는 흐름
1. 기존 BookRoutePreviewView(books:) 입력은 그대로 유지한다.
2. BookRoutePreviewFeature가 BookShelfMapFeature를 자식 상태로 소유한다.
3. 자식이 도서별 소장·서가 연결을 끝내면 BookRoutePreviewRequest가 확정된 입력을 만든다.
4. 부모의 onChange가 요청 변화를 감지해 BookRoutePreviewClient로 계산한다.
5. Client는 기존 BookRoutePreviewTestRouteLoader를 호출한다. 최단 순서·거리·단계 계산은 바꾸지 않았다.
6. 계산 결과는 기존 BookNavigationSession 그대로 보관하고 기존 전체 화면 안내로 전달한다.

상태와 수명
- 미리보기 계산 결과·로딩·오류·층 선택은 Reducer에 둔다.
- 시트 높이·detent·카메라 배치 보정과 cover 닫힘 순서는 기존 View/UI 상태에 둔다.
- 새 입력은 이전 계산을 취소한다. 요청 번호·입력 일치·화면 활성 여부로 늦은 결과를 차단한다.
- 테스트모드 전환은 자식을 nil로 만들고 다음 액션에서 재생성한다.
  TCA ifLet은 비식별 자식을 같은 non-nil 타입으로 덮어쓰는 것만으로는 이전 효과를 취소하지 않는다.
- 화면 종료는 경로 계산, 자식 소장 조회와 지도 작업을 취소한다.

의존성을 합치지 않은 이유
- BookClient는 서지 검색, BookSearchCacheClient는 메모리 TTL·새로고침 정책을 담당한다.
  네트워크와 캐시는 독립적으로 대체·검증해야 하므로 분리를 유지했다.
- 찜·장바구니·검색 기록은 서로 다른 저장 책임이므로 하나의 거대한 Client로 합치지 않았다.
- 중복된 찜 토글만 BookFavoritesClient.toggle로 모았다. 최신 저장값을 읽는 기존 순서를 유지한다.
- BookStorageKey에 기존 저장 키 3개를 모았다. 문자열 값·JSON 저장 형식은 바꾸지 않았다.
- MapKit 재사용 식별자와 방향 화살표 태그는 Coordinator 내부에 모았다. 기존 값을 유지한다.

그 밖의 정리
- 주요 State·Coordinator 캐시를 목적별 MARK로 나눴다. 기존 프로퍼티 이름·초기화 인자 순서는 유지한다.
- UserProfile의 문법 설명 주석을 줄이고 순수 전달 값을 Domain으로 옮겼다.
  주석·공백을 제외한 기존 모델과 전달 값 코드의 동일성도 확인했다.
- 선언이 없는 AppError.swift만 제거했다. 사용 여부가 불분명한 코드를 추측해서 지우지 않았다.
