# C5 실내지도와 현재 위치

Refs #5, #7, #52. 기본 카메라는 기울기 0도의 평면이다. 층 선택과 현재 위치 포커스 버튼을 표시한다. MapKit의 확대·이동·회전·기울임을 지원한다. 층 전환은 도형만 바꾸고 카메라를 유지하며, 명시적인 현재 위치 포커스에서 평면으로 맞춘다.

2026-10-19 결정에 따라 실제 측위·보정과 현장 측위 검증은 마지막 단계로 미루고,
수동 출발점 지정은 보류한다. 현재는 [IMDF 시뮬레이터 위치와 C5 가상 서가](IndoorMapSimulation.md)로
길찾기 개발을 준비한다. Debug Simulator의 합성 위치와 실제 센서 위치를 구분한다.

## 폴더 책임

- App: Root Store를 만들고 지도 Feature를 연결한다. 앱 전체 navigation은 이곳에 둔다.
- Features/IndoorMap: TCA 상태·행동, 지도 화면, MapKit overlay·annotation과 탭 처리를 담당한다.
- Domain/IndoorMap: 지도 요소·좌표·현재 위치, 도형 포함 관계와 샘플 유효성 규칙을 둔다. SwiftUI·MapKit·CoreLocation·TCA에 의존하지 않는다.
- Clients/IndoorMap: 번들 파일 로더와 IMDF DTO·Mapper, 테스트 가능한 지도 의존성을 둔다.
- Clients/Location: Core Location을 비동기 이벤트로 제공한다. Feature는 같은 인터페이스의 재생 위치로 교체할 수 있다.
- Resources: Git에 포함한 개발용 C5 도면을 둔다. [가져오기와 라이선스](IndoorMapData.md)를 따른다.

기존 도메인 `IndoorMapFeature`는 지도 요소를 뜻하는 `IndoorMapElement`로 이름을 바꿨다. 사용자 행동 단위인 TCA `IndoorMapFeature`와 구분하기 위한 변경이다.

## 사용과 상태

1. C5 데이터가 포함된 현재 브랜치를 받은 뒤 앱을 실행한다. 지도 초기 층은 수신된 위치의 ordinal에 해당하는 층이며, 위치가 없으면 도면의 첫 층이다.
2. 왼쪽 층 목록으로 보는 층을 바꾼다. 층 조회는 현재 위치의 층을 변경하지 않는다.
3. 도면·fixture·시설 마커와 목업 목적지에 연결된 가상 서가 핀을 표시한다. C5 fixture를 실제 도서관 서가로 간주하지 않는다. 가상 서가를 누르면 이름을 표시하고 TCA에 서가 키를 전달한다.
4. 홈은 제목·검색 헤더 아래에 전체 폭의 지도를 표시한다. 현재 위치는 오른쪽 위, 층 선택은 왼쪽 아래에 배치한다. 서가 선택 카드의 **경로 보기**로 [경로 설정 화면](IndoorRouting.md)에 들어간다. 수동 출발점 지정·전체 보기·나침반·축척은 표시하지 않는다.
5. Debug Simulator에서는 별도 시스템 권한 요청 없이 로컬 시뮬레이터 위치·층을 수신한다. 실제 기기·Release 또는 `INDOOR_POSITION_SOURCE=live`에서는 기존 Core Location 경로를 사용한다. 현재 위치 버튼에서 필요한 경우 권한을 요청한다. 앱이 비활성화되거나 전체 지도 navigation이 종료되면 위치 스트림과 MapKit 사용자 위치 표시를 중지한다. 홈에서 경로 설정·검색으로 push할 때는 위치 구독을 유지한다.

수동 현재 층/출발점의 내부 action과 client는 후속 화면 연결을 위해 유지한다. 수동 지정은 현재 화면에서 조작할 수 있는 기능으로 안내하지 않는다.

MapKit 카메라 요청은 `IndoorMapSurface`가 window에 붙고 유효한 크기로 배치된 뒤 적용한다. 배치 전 요청은 가장 최근 요청으로 보관하며, 실제 적용 후에만 완료로 기록한다. 동일한 요청이 반복되거나 layout이 다시 발생해도 사용자가 이동한 카메라를 덮어쓰지 않는다.

### 최초 도형 표시 보완 (2026-10-28)

사용자가 드물게 최초 화면에서 층 버튼·서가 번호만 보이고, 줌 조작 후 도형이 나타나는 현상을 보고했다.
원래 간헐 현상의 정확한 원인은 재현 로그로 확정하지 못했다. 도형 등록과 renderer 활성화 사이의
초기 표시 타이밍을 보완하기 위해 층의 overlay를 배열로 한 번에 등록하고,
`mapView(_:didAdd:)`로 활성화된 renderer를 모아 화면 부착·유효 크기·카메라 적용 이후에
도형마다 한 번만 `setNeedsDisplay()`를 요청한다. 지도 타일 다운로드 완료는 대기 조건으로 사용하지 않는다.
같은 도형의 추가 layout·줌·이동에서는 이 재그리기를 반복하지 않으며, 층 교체·화면 해제 시
이전 도형의 대기 작업을 취소한다. 카메라를 다시 맞추거나 일정 시간 지연 후 줌을 바꾸지 않는다.

`IndoorMapInitialRenderingTests`는 화면 부착 전·작은 임시 크기에서의 보류, 사용자 카메라 보존,
중복 콜백, 층 전환·화면 해제 뒤 지연 작업 취소를 검증한다. 실제 3·4층 지도를 각각 3회
새 `MKMapView`로 열어 조작 전 화면에 갈색 책장 도형이 그려지는지도 픽셀과 캡처 이미지로 확인한다.
레이블·층 버튼에 가리지 않은 책장 중심을 최소 10곳 이상 확인하며, 그중 95% 이상이
표시될 때 통과시켜 도형 일부만 나타나는 초기 프레임과 전체 표시를 구분한다.
2026-10-28 iPhone 18 Pro / iOS Simulator 27.0에서 지도 테스트 147개 함수·262회 실행이 통과했다.
실패·skip·xcresult 런타임 경고는 0이며 결과는 `/private/tmp/postech-initial-overlay-coverage.xcresult`다.
이는 원래의 간헐 현상이 모든 기기에서 제거됐다는 보장은 아니며, 실제 기기의 첫 진입도 확인해야 한다.

최초 지도 로딩은 `initialFloor` 요청으로 층 전체 맞춤보다 3배 확대한다. 배율은
`Features/IndoorMap/Rendering/IndoorMapKitView.swift`의 `initialZoomScale`에서 조절한다. `1`은 전체 맞춤,
`3.0`은 3배 확대이며, 전체 외곽 일부가 화면 밖으로 나갈 수 있다. 층 선택이나 시뮬레이터의 층 이동은
카메라 요청을 새로 만들지 않으므로 현재 중심·확대·회전을 유지한다. 현재 위치 버튼은 기존 줌을
유지하며 위치 중심만 이동한다. 내부 `fitMapTapped` action은 기존처럼 해당 층 전체를 맞춘다.

## 위치의 의미

- 실제 센서 모드의 Blue Dot은 유효한 센서 샘플 수신 후 MapKit 기본 사용자 위치 표시를 사용한다. 현재 층이 알려져 있고 조회 층과 다르면 Blue Dot을 숨긴다. 층 정보가 없을 때 좌표로 층을 추정하지 않는다.
- 위치 모델은 센서·수동·테스트 재생·시뮬레이션 소스를 구분한다. 시뮬레이션은 별도 파란 점을 사용하며 native 사용자 위치와 겹쳐 표시하지 않는다. 위치 수신 오류는 지도 위에 표시한다. 수동·재생 위치를 연결하는 화면에서는 각각 보라색·주황색 마커를 사용한다.
- 센서 샘플은 유효한 WGS 84 좌표·0 이상의 유한한 horizontalAccuracy·현재 시각 대비 -5~30초 범위여야 수용한다. 더 오래된 순서 역전 샘플도 버린다. 이 시간 범위는 표시·중심 이동을 위한 초기 정책이며 도착 판정·C5 측위 정확도 보장이 아니다. 수동 위치에는 시간 만료를 적용하지 않는다.
- 위치를 저장하거나 별도 서버로 전송하는 기능, 백그라운드 위치 권한, Always 권한을 추가하지 않는다. MapKit·Core Location은 시스템 서비스를 사용한다.
- 권한은 Core Location의 권한 변경 콜백에서 읽어 캐시하고 새 구독자에게 캐시를 전달한다. 기기 전체 위치 서비스 OFF 구분은 denied 상태에서만 `@concurrent` 조회로 수행한다. 권한 철회는 조회를 기다리지 않고 먼저 전달하며, 취소되거나 이전 권한 상태에 대한 조회 결과는 반영하지 않는다. CLLocationManager 생성·delegate·업데이트 시작/중지는 MainActor에 유지한다.
- C5 층 연결은 `CLFloor.level`과 도면 ordinal의 일치로 처리한다. 실제 기기의 층 기준·정확도는 C5 현장에서 검증해야 한다. 없는 층을 임의로 첫 층에 매핑하지 않는다.

## 검증과 후속 범위

`IndoorMapTests`에서 도면 로딩·내부 ring·평면 카메라·초기 배치 전 카메라 보류와 적용·센서/수동 위치 전환·권한 거부와 철회·유효하지 않은 위치·위치 스트림 취소·재생 위치 구분을 검증한다. 시뮬레이터 검증으로 실제 실내 측위 품질을 대신하지 않는다.

지도 로딩 뒤 routing GeoJSON과 ShelfDirectory를 TCA의 navigation 상태에 읽는다. 데이터셋 해시·지도 층 참조와 목업 목적지 연결을 검증하며, 실패해도 지도·층 선택은 유지한다. [데이터 묶음과 사용 방법](IndoorNavigationData.md)을 참고한다.

도서 담당과 지도 간 책·소장 위치 전달 계약은 아직 정해지지 않았다. 기존 검색 화면의 진입은 유지하며, 추천·책바구니와 지도 목적지 연결은 담당자와 조율한다. 단일 서가 길찾기는 #7에서 구현했고, 경로 안내는 #16 범위다. 이 문서 수정으로 #5를 자동 종료하지 않는다.
