# 겹치는 서가의 경로 안내

Refs [#73](https://github.com/adap-c6-fingerprint/postech-library/issues/73).
2026-11-01 사용자가 같은 층의 인접 후보 중 한 곳까지 안내하고 두 서가를 함께 표시하는 방식을 선택했다.

## 처리 기준

- `BookHoldingShelfResolver`는 확인된 소장 위치 `c3b`(3층 단행본)·`c4b`(4층 제본학술지)로 층을 먼저 제한한다.
- 위치 코드가 없거나 지원하지 않는 구역이면 청구기호만으로 층을 추정하지 않는다.
- `ShelfOverlapPolicy`는 아래의 이슈 명시 인접 쌍과 같은 fixture 번호의 A/B면만 하나의 후보 구역으로 허용한다.
- 후보가 없거나, 여러 층 또는 확인하지 않은 인접 관계에 걸치면 기존처럼 경로를 준비하지 않는다.

| 인접 후보 | fixtureNumber |
| --- | --- |
| 303-B / 304-A | `S-3F-653-B` / `S-3F-651-A` |
| 319-A / 319-B | `S-3F-524-A` / `S-3F-524-B` |
| 321-B / 322-A | `S-3F-528-B` / `S-3F-530-A` |
| 334-B / 335-A | `S-3F-558-B` / `S-3F-560-A` |
| 351-A / 352-B | `S-3F-644-A` / `S-3F-642-B` |

같은 층이라는 조건만으로 서로 다른 소장처나 먼 서가를 묶지 않는다. 새로운 인접 쌍은 실제 관계를 확인하고 정책에 추가한다.

## 경로 선택과 결과 보존

계산 입력 `BookRouteCandidateStop`은 책·소장 정보·후보 전체를 가진다.
결과 `BookNavigationStop`은 대표 목적지 `shelf`와 후보 전체 `candidateShelves`를 함께 가진다.

- 한 권은 실제 A* 이동거리가 짧은 도달 가능한 후보를 선택한다.
- 여러 권은 책마다 후보 한 곳을 선택한 조합과 방문 순서를 함께 비교해 전체 이동거리가 짧은 계획을 선택한다.
  현재 1~3권·권당 최대 두 후보이므로 최대 8개 후보 조합 × 6개 방문 순서다.
- 현재 경로 로더의 3층 311-B 고정 출발 정책을 사용한다. 이번 기능이 실제 사용자 위치를 출발점으로 바꾸지는 않는다.
- 거리가 같으면 후보 fixture ID와 기존 책 입력 순서를 기준으로 일정한 결과를 유지한다.
- 구간 캐시는 책 인덱스 대신 실제 출발·도착 fixture ID를 사용한다. 후보가 달라진 구간에 다른 후보의 거리를 재사용하지 않는다.
- 경로가 없는 조합은 건너뛰고 다른 후보·순서를 계산한다. 모두 실패하면 일부 책만의 경로를 정상 결과로 반환하지 않는다.
- 취소와 지도·노드 자료 오류는 `noRoute`와 구분하고 상위에 전달한다.
- 미리보기의 입력 일치 검사는 선택된 목적지의 차이를 허용하면서 원본 책·소장 정보·후보 전체가 같은지 확인한다.
  안내 시작은 계산된 동일 세션을 사용한다.

선택된 서가는 길찾기 도착 지점이며 책이 그 서가에 꽂혀 있다고 확정한 결과가 아니다.

## 화면

미리보기와 안내 지도는 두 후보를 모두 강조하고 카메라 범위에도 두 후보를 포함한다.
이동 경로는 선택한 대표 서가 한 곳까지 그린다.
미리보기에는 선택한 안내 목적지와 도착 후 두 서가를 확인하라는 문구를 표시한다.
안내·도착 화면은 `후보 서가: 319-A · 319-B`와 `두 서가를 확인해 주세요`를 표시한다.
후보가 하나인 경우에는 기존 단일 서가 표시를 사용한다.

## 청구기호

`BookShelfRangeMatcher`는 `PL2489.논.독92`처럼 중간에 숫자가 없는 한글 구분이 있는 복합 기호를 읽는다.
임의의 한글 안내 문구를 청구기호로 받지 않도록 이 구분은 다음 점 구분 기호가 있을 때만 허용한다.
한글 저자·도서 기호는 가나다순으로 영문 기호보다 앞에 배열한다.
분류 번호의 수치 비교, Cutter 숫자의 소수식 순서, 연도·권차를 제외한 범위 비교와 양 끝 후보 보존은 유지한다.
규칙의 근거는 [포스텍 도서관 청구기호 안내](https://postechlibrary.tistory.com/1127)다.
원본 서가 JSON과 도면·길찾기 파일은 변경하지 않는다.

## 검증

- 현재 제품의 지도·서가 로더, resolver, planner, session 등 Swift 소스 41개를 복사한 macOS 검증 사본에서
  28개 테스트 함수·57개 매개변수 실행이 통과했다. 검증 사본은 리소스 조회의 `Bundle.main`만 SwiftPM의 `Bundle.module`로 바꾼다.
- 다섯 같은 층 겹침, 여덟 층간 겹침의 소장 위치 제한, 대표 후보의 거리·동률·불통 경로,
  세 책의 후보·순서 전체 최소 거리, 기존 단일 서가·방문 순서·공유 서가와 입력 변경 검사를 포함한다.
- 결과 로그: `/private/tmp/issue73-native.log`.
- iOS 테스트에는 `ShelfOverlapRequestTests`와 도착 화면의 후보·문구를 확인하는 OCR 검사를 추가했다.
- Simulator 서비스 연결 실패로 iOS 실행·화면 검증은 아직 완료하지 못했다.
  전체 테스트 빌드도 Icon Studio의 `PobookIcon.icon` 처리에서 실패했다.
- 앱 아이콘만 제외한 검증 사본에서는 iOS Simulator arm64의 앱·`IndoorMapTests`·`BookDetailTests`
  `build-for-testing`이 성공했다. 별도 캐시·산출물 경로와 검증 프로세스의 sandbox 옵션을 명령으로 지정했다.
  저장소의 프로젝트 설정·아이콘·패키지 버전은 변경하지 않았다.
  컴파일 로그: `/private/tmp/issue73-ui-compile.log`.
- 검증 로그에는 기존 테스트 fixture 호출부의 MainActor 경고가 남는다. iOS 테스트를 실행한 결과로 합산하지 않는다.

macOS 검증을 iOS 앱 전체 테스트나 현장 배가 확인으로 간주하지 않는다.
