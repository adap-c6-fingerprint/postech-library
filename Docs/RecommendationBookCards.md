# 추천 도서 카드의 소장 정보 (#88)

이슈 [#88](https://github.com/adap-c6-fingerprint/postech-library/issues/88)의
표지·제목·저자 UI를 유지하고, 하단 도서 카드의 소장 정보 표시를 실제 Primo 조회에 연결한다.
상단 추천 캐러셀은 전달받은 디자인처럼 표지를 표시한다. 상세 화면 디자인·길안내는 이 범위에 포함하지 않는다.

## 연결과 표시

- 카드 목록 표시·변경·재진입과 새 접속 세션에서 소장 정보를 조회한다. 추천·표지 로딩을 기다리게 하지 않는다.
- 기존 `Book` 계약을 유지한다. `BookHoldingsClient`가 `controlNumber` 또는 `id`의 정확한 Alma 자료 번호로 조회한다.
- #75의 조회 서비스·파서·소장 모델과 HTTP 시뮬레이션을 재사용한다. `delivery.holding`을 먼저 읽고 응답의 자료 번호를 정확히 대조한다.
- 본관 소장처를 우선하며 그 안에서 이용 가능한 소장처를 먼저 표시한다. 위치·청구기호·이용 상태는 같은 소장처에서 선택한다.
- 카드 위치 이름의 `단행본` 접두사만 제거해 `단행본3층`을 `3층`으로 표시한다. API 원본과 청구기호는 유지한다.
- 복수 소장 위치는 `외 N곳 소장`으로 알린다. `available`은 초록색 `대출 가능`, `unavailable`은 빨간색 `이용 불가`로 표시한다. 알 수 없는 값을 대출 가능으로 추정하지 않는다.
- 로딩 중에는 자리 표시자를 사용한다. 빈 소장 정보·필드 누락·조회 실패는 각 안내 문구로 표시한다. 실패 시 `소장 정보 다시 불러오기`로 재시도한다.
- 최대 3건씩 병렬 조회한다. 화면을 떠나면 요청을 취소하고 이전 목록·요청의 늦은 응답을 무시한다.
- 성공 응답은 메모리에 최대 1분·200건 보관한다. 화면을 계속 켜 둔 동안의 자동 폴링은 없으며, 이용 상태는 조회 응답 기준이다.

## 설정

키는 Git에서 제외된 `Secrets.xcconfig`에 둔다. Debug는 기존 `PRIMO_API_KEY`로 개발용 조회가 가능하다.
Release의 새 소장 조회에는 기관 키를 보관하는 HTTPS 백엔드 프록시가 필요하다.
`PRIMO_PROXY_URL`을 비공개 설정 파일 또는 배포 빌드 설정에 주입한다.

```xcconfig
// 설정 형식 예시이며 실제 운영 주소가 아니다.
PRIMO_PROXY_URL = https:/$()/library.example.org
```

`dev`에서 통합한 `Validate Release Primo Proxy` 빌드 단계가 Release의 프록시 누락·형식 오류를 차단한다.
기본 주소는 비워 두며 실제 운영 프록시는 아직 확인하지 않았다.
기존 검색·추천 API의 인증 구조는 변경하지 않는다.

## 간단한 확인 방법

1. 추천 화면의 하단 카드에 표지·제목·저자와 소장 위치·청구기호·이용 상태가 표시되는지 확인한다.
2. 정보 없음·네트워크 실패에서도 카드가 유지되고 소장 정보 재시도가 되는지 확인한다.
3. 화면을 떠났다 돌아오거나 새 목록을 표시했을 때 이전 요청의 정보가 섞이지 않는지 확인한다.

테스트: `BookCardLibraryInfoTests`, `HomeLibraryInfoTests`, `PrimoHoldingsMapperTests`,
`HomePopularBooksTests`, `IndoorMapSerialTests.HomeBookCardScreenTests`.
HTTP 실행 방법과 mock 출처·한계는 [Primo 시뮬레이션 기록](../postman/simulations/primo-holdings/primo-holdings.context.md)에 있다.

2026-10-28 검증: 관련 테스트 19개 함수·25회 실행이 통과했고 실패·skip·런타임 경고는 없었다.
실제 Swift 6 HTTP 서비스와 카드 변환을 Postman 로컬 시뮬레이션에서 실행해 정상·오류 응답을 확인했다.
실제 POSTECH 읽기 전용 조회에서도 『사피엔스』의 `단행본3층 CB113.H4 .H3713 2015`,
`available`, 추가 소장 위치 2곳이 카드 값으로 변환됐다. 테스트는 개인 Xcode 설정과 키를 보존하는 검증 사본에서 실행했다.
운영 프록시 배포·Release 환경 접속과 항상 최신인 대출 상태를 보장하는 검증은 포함하지 않는다.

리뷰 보완: 화면 테스트는 네 가지 소장 상태를 각각 렌더링하고 Vision으로 이미지의 문구를 읽어
위치·청구기호·대출 가능·이용 불가·정보 없음·조회 실패를 직접 단언한다. 테스트 데이터는 카드 폭 안에서
문구 전체를 읽을 수 있게 구성했으며 공백만 제거해 비교한다. 네 가지 화면 시나리오가 모두 통과했다.

최신 `dev`의 #75 통합 후 추천 카드·소장 조회·서가 지도 관련 26개 테스트 함수·36회 실행과
Release 설정 검사 4개가 통과했다. 공유 캐시는 1분을 유지하고 Release 설정 검증 단계도 보존했다.
