# 층 보정 v3

사용자가 제공한 `floor-v3-implementation.md` 개정 1을 적용한다. 기준은 `dev`의 `f720f36`이다. 이 기준에는 v1 추정기·v2 관문·기압 클라이언트가 없어 v3를 새로 연결했다.

## 판단과 설정

현재 층은 **CLFloor가 투표한 기준층 + 기압계가 센 층 이동량**이다. `CLLocation.altitude`는 사용하지 않는다.

| 항목 | 기본값 | 역할 |
| --- | --- | --- |
| 층고 | 4.26m | 제공 문서에 보고된 실측 평균 |
| 이동 문턱 | 층고의 0.6배, 같은 방향 표본 2개 | 짧은 기압 변동을 거른다 |
| 중앙 공간 | 모든 층의 `opentobelow` 윤곽 및 경계 1.5m | 기압계가 살아 있을 때 CLFloor 가중치를 0.1로 낮춘다 |
| 표의 기억 시간 | 기압계 있음 120초, 없음 3초 | 간섭과 짧은 층 변화를 완화한다 |
| 기준층 교체 배수 | 최초 확정 전 1.0, 이후 1.5 | 시작 직후 잘못된 층을 바로잡고 확정 층을 보호한다 |
| 최초 확정 | 기준층 표가 다른 후보보다 10 이상 앞섬 | 이후 `unconfirmed`가 되어도 확정 이력은 유지한다 |
| 유효 층 누락 유지 | 기압계 있음 120초, 없음 10초 | 한도를 넘으면 `unknown`을 전달하고 초기화한다 |

기압계가 센 이동을 CLFloor가 되돌리던 v1 규칙은 없다. 출발 층을 계속 보고하는 CLFloor는 40초 동안 투표에서 제외하고, 이후 보통 투표로 반영한다. 설정은 `FloorEstimator.Configuration`과 `AtriumZone`에서 관리한다.

## 위치 흐름

- `LocationSessionFeature`가 위치·기압 구독을 소유한다. 위치 승인 후에만 기압을 구독하고, 권한 해제·앱 비활성화 시 취소한다. 중앙 공간 지도 읽기도 취소하고 다음 활성화 시 필요하면 재시도한다.
- 센서 위치의 층만 바꿔 `indoorLocation`에 전달한다. 좌표·방향·측정 시각과 수동·리플레이 위치는 보존한다.
- 기압 표본은 추정기만 갱신한다. 다음 위치 이벤트에 층을 반영하므로 GPS의 유효 시간을 연장하지 않는다.

## 검증 범위와 현장 확인

Swift Testing에서 문서의 S1~S21(세부 항목 포함 26개), R1~R3, 중앙 공간의 실제 번들 윤곽·거리, 최초 확정과 만료, 위치 세션 구독 취소·수동 위치 보존을 검증한다. R 재생은 문서에 요약된 관측 구간과 **가상 기압**이며 실제 CSV·센서 정확도를 검증한 결과가 아니다. 측정 CSV는 저장소에 넣지 않는다.

실기기에서는 기압계 권한·수신을 먼저 확인한 뒤 중앙 공간에서 5~10분 머무르기, 계단 상승·하강, 엘리베이터, 출입문 통과를 확인해야 한다. 문서의 근거는 한 기기·계단 하강 기록에 한정된다. 오랫동안 잘못된 초기 CLFloor, 지속적인 기압 오차(S19), 기압계 미지원·권한 거부, 중앙 공간에서 확정되지 않는 층은 한계로 남는다. 수평 좌표 튐과 외부 위치 정책은 이번 범위에 포함하지 않는다.

### 초기 층 튐 QA 재현

사용자가 실제 5층에서 실행한 뒤 약 5초 만에 4층으로 바뀌었다가 5층으로 돌아오는 현상을 보고했다. 당시 센서 입력을 기록한 자료는 없어 실제 원인은 확정하지 못했다.

현재 Swift 추정기에 일정한 기압 높이를 넣으면서 CLFloor를 0.6초에 5층, 4.6초에 4층, 8.6초에 5층으로 입력하면 같은 전환이 재현된다. 기압계의 층 이동량은 계속 0이다. 준비 구간의 첫 관측은 표가 0.1이지만 다음 관측은 4초 간격을 반영해 0.4이고, 최초 확정 전 교체 배수가 1.0이므로 잘못된 관측 한 번으로도 기준층이 바뀔 수 있다. 중앙 공간 가중치를 모두 0.1로 낮춰도 표의 상대 비율은 같다.

배수만 1.2 또는 1.5로 바꿔도 이 입력은 막지 못한다. 다른 층으로 전환하기 전 연속 관측 확인 같은 별도 안정화 조건이 필요하다. 이 PR은 제공된 v3 규칙을 유지하며 해당 초기 튐은 남은 한계다.

### 2026-11-15 확인 결과

- iOS 27.2 iPhone 18 Pro 시뮬레이터에서 전체 102개 테스트, 매개변수 포함 169회 실행 통과.
- 문서의 Python 참조 구현을 저장소 밖에서 실행해 S·R 기대값과 일치함을 확인했다. Swift의 시나리오·거리 테스트도 통과했다.
- `xcodebuild test`와 `xcodebuild build -configuration Release`를 프로젝트·scheme `fingerprint-library`, destination `F63B1138-83EC-4598-892C-8BB8A698F2A2`, `CODE_SIGNING_ALLOWED=NO`로 실행했다. Debug·Release의 생성된 Info.plist에는 동작 및 피트니스 사용 목적 문구가 있다.
- 알고리즘과 기압계 연결을 한 브랜치에 적용했다. 디버그 출력·표시와 이를 위한 상태·코드는 포함하지 않는다. 지도 읽기도 앱 비활성화 때 취소하며, 권한 승인 이후에만 기압을 구독하도록 수명을 관리했다.
- 실제 센서, 현장 정확도, 권한 거부 시 콜백의 구체적인 오류 코드는 실기기에서 확인해야 한다.

## 확인한 Apple 자료

- [CMAltimeter](https://developer.apple.com/documentation/coremotion/cmaltimeter): 지원·권한 확인, 상대 고도 업데이트 시작·정지, `NSMotionUsageDescription`.
- [CMErrorNotAuthorized](https://developer.apple.com/documentation/coremotion/cmerrornotauthorized): 권한 오류 코드. 실제 기기의 콜백 오류 코드는 현장 확인이 필요하다.
- [Privacy HIG](https://developer.apple.com/design/human-interface-guidelines/privacy): 필요한 시점에 시스템 권한 요청.

설치된 iOS 27.2 SDK의 `CMAltitude.h`에서 기압 단위가 kPa이고, `CMAltimeter.h`에서 오류 후에도 시작·정지 호출을 짝지어야 함을 확인했다.
